## About This Repository

This repository contains the complete empirical corpus generated by the application of the **AIRO (AI Studio Research Orchestrator)** protocol to three original teacher-AI co-design cases in mathematics education.

Each case consists of **16 structured Markdown documents (E00–E15)**, produced by applying the AIRO protocol to the full interaction history between the teacher-researcher and Google AI Studio during the development of an interactive mathematical simulator. All documents apply a strict **epistemic tripartition**:

- **Evidence** — data extracted literally from the interaction logs
- **Inference** — explicitly marked logical deductions
- **Interpretation** — cross-theoretical analysis anchored in the research framework

This corpus constitutes the audit trail for the findings reported in the associated manuscript. It allows independent verification of: interaction chronology, development prompt taxonomy, qualitative codebook, architecture decision records (ADRs), agency episode mapping, and the bootstrap paradox documented as LAC-001.

## Case Descriptions

### Case 01 — Kinematic Simulator
**Domain:** Linear Systems of Equations / Uniform Rectilinear Motion (MRU)  
**Platform:** Google AI Studio  
**Period:** 7–27 July 2026  
**Status:** Founding case of the AIRO protocol

This is the corpus from which the AIRO protocol was developed and validated for the first time. It is the only case in which the protocol and the object of study co-evolved: the teacher-researcher developed the simulator *and* used that process to formalise the protocol that documents it. This recursive property — the protocol applied to the corpus that generated it — is identified in the manuscript as the **bootstrap paradox**, concretely documented here as **LAC-001**: the interaction history begins at T-001 (a visual asset refinement), with the base application already functional, inferring a "Turn 0 absolute" that predates the documented record.

Key architectural decisions documented:
- **DEC-002:** `disabled={isSimulating}` — locking all input sliders during simulation runtime to protect the cognitive model of MRU
- **DEC-003:** `strokeDasharray="8 8"` — conditional dashed rendering to make coincident lines (SPI) visually perceptible
- **DEC-005:** Plain-text local passwords (`velocidadefuriosa`, `profmat`) as pedagogical gatekeeping mechanisms

### Case 02 — Pixels and Matrices
**Domain:** Linear Algebra (matrix transformations, non-commutativity)  
**Platform:** Google AI Studio  
**Status:** Partial documentation — Synthesis layer (E09–E15) applied retrospectively

This case documents the development of an interactive Linear Algebra simulator exploring matrix non-commutativity through simultaneous visual rendering of composite transformations. Documentation covers the Synthesis layer (E09–E15); the Extraction and Analysis layers were not formally archived during development, reflecting the non-linear genesis of the AIRO protocol.

Key architectural decisions documented:
- **DEC-001:** Simultaneous dual rendering of M₁×M₂ and M₂×M₁ with chromatic distinction
- **DEC-003:** Simplification of navigation labels from descriptive metalanguage ("Part II: Ruptura") to neutral numbering ("Part 3") to prevent heuristic anticipation
- **DEC-004:** Removal of footer and translation to English — application of Mayer's Coherence Principle

### Case 03 — Tidal Simulator
**Domain:** Trigonometric Functions — f(x) = a + b·sin(cx − d)  
**Platform:** Google AI Studio  
**Period:** July 2026  
**Status:** Prospective documentation (E00–E15 complete)

This case documents the development of an interactive trigonometric simulator featuring two complementary learning modes: a Beginner Mode with parameter sliders and an Advanced Mode requiring manual algebraic input. The case was documented prospectively across all 16 AIRO states.

Key architectural decisions documented:
- **DEC-002:** Differentiated validation threshold (1.0 in Beginner Mode, 0.5 in Advanced Mode) — scaffolding calibration
- **DEC-003:** `mathjs` library for safe algebraic string parsing — preserving free-form student input without `eval()` risks
- **DEC-004:** `max-h-[35vh]` / `lg:flex-row` layout constraints — no-scroll design for visual continuity between sliders and graph

## Qualitative Codebook

The following six codes were identified through constant comparative analysis across the three cases. Cross-case convergence was confirmed for `[COD-SUBT]` and `[COD-CONT]`, which appear in all three simulators.

| Code | Name | Definition |
|------|------|------------|
| `[DID-PROT]` | Cognitive Model Protection | UI mechanisms preventing runtime manipulation of physical/mathematical concepts |
| `[DID-VIS]` | Geometric-Mathematical Visual Representation | Adaptation of graphical components to illustrate overlapping or hidden mathematical phenomena |
| `[UX-FEED]` | Asymmetric Visual Feedback | Differentiated error feedback proportional to the cognitive weight of the context |
| `[LOG-EXC]` | False Positive Mitigation | Strict refinement of logical conditions to avoid blocking valid mathematical scenarios |
| `[COD-SUBT]` | Technological Subtraction | Deliberate removal of technical complexity or generative affordances to protect pedagogical focus |
| `[COD-CONT]` | Visual Continuity | Interface modifications unifying cause and effect within the same viewport |
